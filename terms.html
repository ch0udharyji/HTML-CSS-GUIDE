Basic Terms & Concepts

The absolute beginner's dictionary. Understand exactly what these foundational building blocks are and how to avoid common mistakes.

Tags vs. Elements vs. Attributes #

What are they? This is the fundamental vocabulary of HTML.

- A Tag is the keyword enclosed in brackets: <p> and </p>.

- An Attribute is extra info inside the opening tag: class="text".

- An Element is the entire thing: the opening tag, the content, and the closing tag.

Common Error: Incorrect Vocabulary
Saying "I added a class tag." You added a class attribute to an element.

Self-Closing Tags #

What is it? Elements that don't wrap around text or other elements, so they don't need a closing tag (like </img>). Also called "empty elements".

Examples: <img>, <br>, <hr>, <input>.

Common Error: Trying to nest content inside them
Writing <img src="x.jpg">Text</img>. This is invalid HTML and the browser will ignore or break it.

<head> vs. <body> #

What is it? The strict division of an HTML document.

Why use it? The <head> contains metadata (invisible settings, CSS links, SEO data). The <body> contains the actual visible content of the page.

Common Error: Visible content in the head
Accidentally putting an <h1> or an image inside the <head>. The browser will forcefully eject it into the body, sometimes breaking your layout in the process.

File Paths (URLs) #

What is it? How you link to images, CSS, or other pages.

Absolute: The full web address starting with https://...

Relative: Pointing to a file on your own computer/server. ./ means "current folder". ../ means "go up one folder level".

Common Error: Hardcoding local paths
Writing src="C:/Users/Bob/Desktop/image.jpg". This works on your computer, but will immediately break when you upload your website to the internet.

<div> (Division) #

What is it? A generic block-level container with absolutely no special meaning.

Why use it? Used to group elements together for styling with CSS or manipulating with JavaScript.

Common Error: "Div Soup"
Nesting too many meaningless <div>s instead of using semantic HTML. This hurts accessibility (screen readers) and SEO.

<span> #

What is it? A generic inline container. Like a div, it has no meaning, but it does not force a line break.

Why use it? To target a specific chunk of text inside a paragraph to style it differently (e.g., making one word blue).

Common Error: Block inside Inline
Putting a block element (like a <div>) inside a <span> is invalid HTML and breaks layouts.

Semantic Tags #

What is it? HTML tags that describe their meaning to the browser (e.g., <header>, <nav>, <main>).

Why use it? Crucial for screen readers and search engines to understand page structure.

Common Error: Misusing <section>
Using a <section> purely as a styling wrapper. A section should logically group related content and usually contains a heading.

Attributes (Classes & IDs) #

What is it? Identifiers added to tags: class="" and id="".

Why use it? To provide hooks for CSS and JS to grab onto.

Common Error: Duplicate IDs
An id must be 100% unique on a page. Using the same ID twice breaks JavaScript selection logic. If you need it twice, use a class.

The Viewport Meta Tag #

What is it? <meta name="viewport" content="width=device-width, initial-scale=1.0">

Why use it? It forces mobile browsers to render the page at the exact width of the phone screen, rather than zooming out to show a tiny desktop version.

Common Error: Forgetting it
If your media queries aren't working on your phone, it's almost always because you forgot to include this tag in the <head>.

The DOM (Document Object Model) #

What is it? The browser's internal map of your HTML. It builds a "tree" of objects in memory.

Why it matters? JavaScript doesn't read your HTML file directly; it interacts with the DOM to change the page dynamically.

Common Error: DOM Not Loaded
Trying to run JavaScript before the browser has finished building the DOM results in "Element is null" errors. Fix by placing <script> at the bottom of the body or using the defer attribute.

CSS Selectors #

What is it? The part of the CSS rule that dictates exactly which HTML element(s) you are trying to style (e.g., .btn or #header).

Common Error: Missing the Dot or Hash
Writing container { ... } instead of .container { ... }. Without the dot, CSS thinks you are looking for an HTML tag literally named <container>.

The Cascade #

What is it? The "C" in CSS. It's the algorithm the browser uses to decide what styles apply. The fundamental rule is: styles written further down in the document overwrite styles written earlier.

Common Error: CSS File Order
Linking your custom CSS file before a framework's CSS file in the HTML. The framework will overwrite your custom code because it loads last.

CSS Inheritance #

What is it? The behavior where certain CSS properties (mostly typography like color and font-family) automatically pass down from parent elements to child elements.

Common Error: Expecting everything to inherit
Properties like border, padding, and margin do not inherit. You cannot set padding: 10px on the body and expect every child to have padding.

CSS Specificity #

What is it? The point-scoring system browsers use to resolve conflicts when multiple rules target the same element.

Hierarchy: Inline Styles > IDs > Classes > Element Tags.

Common Error: The !important Trap
Using !important to force a style to win. This breaks the natural cascade and makes your CSS incredibly difficult to maintain and overwrite later.

The Box Model #

What is it? The concept that every HTML element is a rectangular box comprising: Content, Padding (inner space), Border, and Margin (outer space).

Common Error: Width Blowouts
By default, padding is ADDED to an element's defined width, causing it to overflow the screen. Fix this globally by setting * { box-sizing: border-box; }.

Display Property #

What is it? Determines how an element takes up space. block takes the full width. inline wraps with text. none hides it entirely.

Common Error: Sizing Inline Elements
Trying to set a width or top/bottom margin on an inline element (like a <span>). It won't work! You must change it to display: inline-block; or block first.

Positioning #

What is it? Taking elements out of the normal top-to-bottom document flow.

Types: relative, absolute, fixed, sticky.

Common Error: Escaping Absolute Elements
Giving a child position: absolute; but forgetting to give its parent position: relative;. The child will fly up the page and position itself relative to the entire screen.

Z-Index #

What is it? Controls the 3D depth (stacking order) of elements on the page.

Common Error: Z-Index does nothing
z-index only works on elements that have a position value other than static (e.g., relative or absolute). If it's static, z-index is ignored.

CSS Units #

What is it? How we measure size. px (absolute pixels), rem (relative to root font size), % (percentage of parent), vh/vw (percentage of the screen/viewport).

Common Error: Using px for fonts
Setting fonts in px prevents visually impaired users from scaling up the text using their browser preferences. Always use rem for typography.

Color Formats (Hex, RGB, HSL) #

What is it? How browsers read colors.

Hex: #ff0000 (Base-16 alphanumeric code).

RGB: rgb(255, 0, 0) (Red, Green, Blue integers).

HSL: hsl(0, 100%, 50%) (Hue, Saturation, Lightness - easiest for humans to tweak mathematically).

Media Queries #

What is it? CSS rules wrapped in a condition (e.g., @media (max-width: 768px)). It's the engine behind all Responsive Design.

Common Error: Desktop-First design
Writing all your desktop CSS first and then struggling to crush it down for mobile. Best practice is "Mobile-First": write the mobile CSS natively, and use min-width queries to expand it for desktop.

Vendor Prefixes #

What is it? Strings like -webkit- (Chrome/Safari) or -moz- (Firefox) placed before experimental CSS properties.

Why use it? It allows developers to use brand-new CSS features before they are fully officially adopted by the web standards committee.

Client vs. Server #

Client (Frontend): The user's web browser. It parses HTML, paints CSS, and executes JavaScript.

Server (Backend): A computer sitting in a data center somewhere. It holds a database and sends the HTML/CSS files to the Client when requested.

HTTP vs. HTTPS #

What is it? The language/protocol computers use to talk to each other over the web.

The "S": Stands for Secure. Without HTTPS, any data a user types (like passwords) is sent as plain, readable text over the internet. Browsers now heavily penalize non-HTTPS sites.

Browser Cache #

What is it? Browsers download and save your images and CSS to the hard drive so they don't have to re-download them on every page visit. This makes the web vastly faster.

Common Error: Stale Cache
You edit your CSS file, refresh the page, but the colors didn't change! The browser is stubbornly loading the old CSS file from its cache. Fix this by doing a "Hard Refresh" (Ctrl+Shift+R or Cmd+Shift+R).

Developer Tools (DevTools) #

What is it? A suite of tools built directly into every modern browser (usually opened by pressing F12 or Right-Click -> Inspect).

Why use it? It is the single most important tool you have. You can live-edit HTML, tweak CSS colors, test mobile views, and read JavaScript error logs.

Minification #

What is it? The process of automatically removing every single space, tab, and line-break from a CSS or JS file.

Why use it? Computers don't need spaces to read code. Minifying code dramatically shrinks the file size, making the website load faster. Files like style.min.css are minified.

SEO & A11y #

SEO (Search Engine Optimization): Designing your HTML so Google's bots can easily read it and rank your site higher in search results. Heavy use of Semantic Tags and Meta tags helps this.

A11y (Accessibility): Designing your HTML so visually impaired users can navigate your site using keyboard tabs and screen-reading software. (A11y is an abbreviation: A + 11 letters + y).
